# RECOIL X Update A B6 engine audit

Reviewed on November 24, 2026 against production release source `61c77f3`. The review covered the browser frame loop, Curator renderer and timers, multiplayer simulation and delivery, match settlement, and SQLite upgrade and recovery. Measurements below used isolated fixtures on Node 24. Production capacity and physical-device frame rates remain unmeasured.

## Findings in priority order

| Priority | Finding and evidence | Player impact | Next change and acceptance test |
|---|---|---|---|
| High | Match rewards span separate transactions. After the core settlement, an exception in an award handler is logged and the room advances to results. No durable retry is scheduled in this path. [Settlement](../server/overdrive.mjs#L434) · [Award handlers](../server/server.mjs#L166) | A player can see a finished match while a progression reward remains missing. This is a source finding. No production loss was observed. | Persist a pending settlement keyed by match ID and retry incomplete awards. Simulate a storage failure between handlers, restart, and verify every eligible reward arrives once. |
| High under load | Scheduled SQLite snapshots execute synchronous VACUUM on the simulation thread. A 71,319,552-byte synthetic snapshot occupied that thread for 104.4 ms in one local run. The nominal match tick is 50 ms. [Backup](../server/z5-backups.mjs#L28) · [Tick scheduling](../server/overdrive.mjs#L519) | Every active room can miss updates during a snapshot. Actual pause duration depends on database size and host storage. | Run backups on a separate connection in a worker or process. Measure p95 and p99 tick intervals during backups on a staging copy and verify snapshot integrity. |
| Medium | Movement integrates at most 95 ms per server callback while the round deadline uses elapsed wall time. On an empty movement path with identical held input, five 50 ms updates moved a player 1.450 units. One 250 ms update moved them 0.551 units. [Simulation](../server/overdrive-match.mjs#L383) | During a stall, players lose movement time while the round clock advances. | Measure host tick delays first. Evaluate bounded substeps with the same fixture, then verify collisions, cooldowns and stale inputs before changing simulation timing. |
| Medium | WebGL context restoration unconditionally clears the pause flag after rebuilding GPU state. [Context recovery](../index.html#L4088) | A solo player who paused before a GPU reset can return to active simulation underneath a pause screen. This path was reviewed in source. | Preserve the prior pause state. Force a context loss and restore in both paused and active solo games and verify the menu, input and simulation agree. |
| Medium | Solo Curator decrements the timer once per interval callback. Co-op evaluates an absolute server deadline. [Solo timer](../server/a-curator.js#L150) · [Co-op timer](../server/a-curator-rooms.mjs#L9) | A backgrounded or stalled tab can extend a timed solo playtest, giving a creator a different result from co-op. | Choose a pause-on-hide rule or an elapsed-time deadline, display that behavior and test a delayed callback. |

## Release evidence

- **Migration and recovery.** Created an account using the previous production server, opened its SQLite file with B6, restarted B6 and read the same account with its original session. The upgrade created one private snapshot. Its integrity check passed and the previous Z.5 server successfully read the account from that snapshot. The rehearsal used generated account data.
- **Multiplayer and progression.** The B6 candidate passed 202 automated tests. Coverage includes reconnect through a completed custom FPS match, reward exclusion for custom maps, and title changes visible to both lobby clients. Two Chromium sessions at desktop and touch-emulated phone sizes also retained their positions, shared target and deadline across a Curator screen change. [Candidate validation](https://github.com/RecoilXDev/Recoil-X/actions/runs/45381049310)
- **Rendering.** In the 320-column empty-arena fixture, Curator's first-person camera used 4,236 wall lookups per frame, down from 44,844. Camera tests cover wall depth, diagonal traversal, arena bounds and sprite occlusion. A Chromium solo playtest rotated the camera and collected the final target. Physical GPU frame time, peak memory and thermal throttling still need device measurements. [Camera tests](../tests/update-a-curator-camera.test.mjs)
- **Release identity.** Production health exposes `update-a-b6`. The deployment workflow compares the served Control Center and Curator scripts byte-for-byte with the release sources. The previous production revision was `0c68674`. [Deployment workflow](../.github/workflows/deploy-alwaysdata.yml)
